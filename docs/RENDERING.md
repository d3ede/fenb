# FENB 0.8b

FENB is a graphics mod for Flyff, inspired by ENBSeries. It uses a Windows x86 Direct3D 9 proxy, C++20, precompiled shaders and a native Dear ImGui settings panel.

## Controls and profiles

- **Optimization** contains shop-sign range, separate filters for native player decoration, player skill effects and pet effects, and visibility controls for other players, monsters and pets. Effect filters and shop limiting default off; actor rendering defaults on with native draw distances. These controls are independent of the FENB effects master and retained when changing image profiles or using Reset all. Explanations are limited to two sentences per option.
- Shop-sign limiting is off by default and independent of the effects master switch. The radius is measured in world units from the local character. The local character's own sign is retained. On the verified Homesickness ABI, a scoped, bounded vendor-render list omits distant signs and restores the exact original pointer and count after rendering. It does not remove actors, modify shop contents, stop simulation or send trade requests. Unknown layouts disable this control. Image profiles and Reset all retain the user's shop-limit choice and radius.
- Native effect controls use the client's existing non-skill/skill render predicates for player-owned SFX. Both native world-render call sites are validated before installing reversible hooks. The selected flags are overridden only during RenderObject and restored exactly on return; world processing, simulation dispatch and the application's environment-render vtable are unchanged. The switches include the local player's effects. Unknown field layouts or call targets disable these controls; an already-replaced call is not overwritten. This is separate from FENB's particle styling, which enhances existing effects instead of hiding them.
- Pet filtering additionally guards the five-byte SFX virtual render dispatch and the native AI checks for following and egg/system pets. It resolves the source through the verified native control map; only an unavailable source falls back to the destination. A valid monster source is never reclassified through a player/pet target. The pet switch ignores the effect's skill flag and includes the local pet; player decoration and skills remain independent. Filtering changes no pet model, animation, buff, pickup, lifetime or simulation data, and leaves unknown owners visible. The same destination fallback covers player effects whose source has disappeared, but offline traders with unresolvable owners still require live verification.
- Actor visibility has independent enable switches and camera distances. Each slider runs from near on the left to **Default** on the right; reset also returns to that right endpoint. Its maximum comes from the guarded native 3×4 culling-distance table, rather than an arbitrary larger range. Existing INI distance keys remain compatible: zero is the internal native-distance sentinel, and smaller saved limits retain their world-unit values. Saved limits at or above the native maximum normalize to native when that supported control is opened. The controls only restrict the native view and cannot extend the game's draw distance. The local character is always retained. Following/system pets use the guarded native AI types; other non-player movers use the native IsPeaceful field/value so peaceful NPCs remain visible, including when combat mobs are hidden. Invalid distances and unknown object types remain visible. The guarded actor qsort call compacts only the bounded 5000-entry render list before native sorting and view-pointer publication, so model, equipment, name and shadow loops consume the same list. World-cell arrays, simulation, movement, target-selection lists and networking are untouched. Known owned SFX and shop captions follow actor visibility, including pets; unresolved effect owners remain visible. Multi-device requests combine visibility by intersection and positive distance limits by minimum, and releasing a request restores the remaining owners' choices. Mapping tests verify installation/removal alongside FPS/background adapters; live client scenes still require verification after restarting with the DLL.

Resource forwarding uses a bounded 256-entry thread-local lookup cache. Registering or retiring a wrapper publishes a registry generation; a cached lookup is reusable only for the same pointer and generation. Misses retain the synchronized registry lookup, including native pointers. The cache holds no COM references, changes no DirectX draw/state calls and does not alter shader processing, model visibility or effect settings. `tests/resource_benchmark.cpp` provides a repeatable resource-binding microbenchmark against a selected DLL; its timing is not a live-game FPS measurement.

- **Shift + Enter** opens and closes the panel without opening game chat. Each opening centers the panel and returns to the main image page. The open panel can still be moved.
- **Effects** enables or disables all FENB rendering. Color correction, Bloom and WaterFX also have individual switches.
- **Right Shift + F12** toggles the master effects switch immediately, with or without the panel. Repeated keydown messages do not toggle it repeatedly; the chord is not forwarded to the game. Left Shift + F12 and ordinary F12 retain their native behavior.
- **World**, between the image page and **Language**, opens local time and weather controls. Each section has an independent enable switch: off follows the game. Drag the time slider in one-minute steps, type `HH:MM`, or use the arrows. **Freeze time** holds the selected hour; otherwise it advances at the native clock's pace. Time remains active and editable with image effects disabled, including comparison mode and **Right Shift + F12**. Weather offers **Clear**, **Rain** and **Snow**, with a live precipitation-intensity slider. Both overrides default to off; weather continues to respect the master effects switch.
- The language dropdown switches between **English** (first and default), **Русский**, **Español** and **Português (Brasil)** immediately. Its compact caption reads **EN**, **RU**, **ES** or **PT**. The choice is saved as `language=en`, `ru`, `es` or `pt` in `[General]` of `FENB.ini`; profiles and effect resets preserve it. Older configurations without this key use English. Custom profile names and filenames stay unchanged.
- Drag a slider, double-click its track to reset it, or click the number to type. The small arrow buttons use a parameter-specific step. The reset icon is shown for changed values.
- Edits save automatically to `FENB.ini`. **Ctrl + S** saves immediately.
- **Create…** beside the profile selector, or **Create profile…** inside its dropdown, saves the current settings under a name. Type the name and press **Save**; the profile appears in the selector. For a loaded custom profile the toolbar offers **Save…**. Existing names require the explicit **Replace profile** button. Files live in `FENB-presets`; compatible `.ini` files can also be copied into that folder.
- The image page groups links to **Light and atmosphere**, **Antialiasing**, **WaterFX** and **Optimization** above tone, highlights/shadows, color balance and Bloom. Select an item in the left navigation to edit its parameters on the right. Names remain readable when an effect is off; filled and outlined status marks show its state. The image breadcrumb returns to this page.
- **Light and atmosphere** groups SSAO, Sun Rays, SkyFX, fog, depth of field, adaptation, lighting balance, vegetation, local lighting, surface reflections and particle processing. WaterFX separates waves, material, depth and reflection settings. **Antialiasing** has separate FXAA, SMAA and hardware MSAA views; FXAA and SMAA remain mutually exclusive. Optimization groups the shop-sign limit and native owner-based effect filters.
- **Reset parameters** below the selected controls resets only that group's values. Effect enable switches, other groups, language and client preferences are preserved. Color correction has one master for tone, highlights/shadows and color; WaterFX has one master for all water groups. Views containing only an enable switch do not show a parameter-reset action.
- Narrow panels replace the left navigation with a grouped dropdown and keep the settings pane full width. Navigation and settings scroll independently when vertical space is limited. Selections belong to each device's panel and do not change or add configuration keys.

**Default / Основной** is the built-in starting profile. Its entire WaterFX block preserves the owner's active water configuration: 0.05 wave shading, 9.5 wavelength, 0.4 speed, 0.8 ripples, 0.74 opacity and sky, detailed SSR, and caustics disabled. Other effects form one combined visual setup: moderate SSAO and Bloom, a stronger daylight ray source, recognized day/night sky and clouds, distant height fog, subtle far DoF without near blur, capped adaptation, warm local surface lighting, SMAA and night foliage fill.

The built-in list displays **Default**, **Default (High-end PC)**, **Default (Low-end PC)**, **Default (Potato)**, **Default (Blue Water)** and **Default (Cyan Water)**, followed by **Default (Warm tones)**, **Default (Cool tones)** and **Default (Soft colors)**. The retained Default, Low-end, Potato and water variants keep their existing profile identities and settings. Clear water, Golden light, Soft atmosphere and Night lights have been removed from the built-in list.

High-end PC retains Default's color and water appearance while enabling detailed effect quality, particle processing and material-aware paving/stone reflections. Water reflections use SSR Quality at full resolution with 48 ray steps and 12 refinements; subtle caustics are enabled. These are screen-space reflections: hidden and off-screen geometry remains unavailable. Hardware MSAA is still a separate user choice. Default and the other regular profiles retain their existing quality switches; particle processing and detailed effect quality remain off there.

Low-end PC differs from Default only by disabling SSAO. Potato retains the default color, sky, brightness adaptation and tone balance, keeps bloom at quarter dimensions and uses FXAA instead of SMAA. It disables SSAO, sun rays, fog, DoF, local lighting, WaterFX and refractive water footsteps. This avoids optional water/depth and lighting work while retaining the main color and exposure treatment; atmospheric effects and native water differ visibly. The profile cannot guarantee a particular FPS gain.

Blue Water and Cyan Water add contrasting water treatments while retaining the default image settings. Warm tones, Cool tones and Soft colors change only color correction: mild warm/cool balance or restrained saturation and softer contrast, with controlled highlights and lifted shadows. They retain Default's water, Bloom, scene effects and quality, without forcing time or weather.

All nine profiles are compiled into the DLL; the default image settings come from `config/FENB.ini`, with named variations in `config/builtins.json`. `node tools/embed-presets.mjs` regenerates `src/generated/presets.hpp`, and both build paths keep it in sync. No shipped `.ini` is added under **My profiles**. Custom files remain independently supported. Image-profile changes preserve the master switch, language, hardware/FPS choices and local time/weather controls. Modified built-ins retain their translated name with an asterisk, and can be saved as a custom profile. Updating the DLL preserves an existing configuration's saved effect switches; select a built-in or change the switches manually to use the new defaults.

The lower-left corner shows the public version, **0.7d**, followed by save status. Public versions use the form `digit.digitletter`; suffixes run from `a` through `h`, then the minor number increases.

The panel uses Windows Tahoma with regular text and moderately strengthened headings. Small neutral group headings separate the navigation; selection uses the existing violet accent. Parameter labels sit above thin sliders, with numeric inputs, step buttons and changed-value resets aligned to the right. The Profile label and Effects caption retain their existing styling. Tahoma is loaded from the Windows Fonts directory and is not distributed with FENB. If it is unavailable, the embedded, SIL OFL-licensed Inter subset provides both text roles.

The optional panel cursor acquires a balanced negative Windows cursor-display count. Late native SetCursor calls cannot display a second cursor; closing the panel, losing focus and device recovery release that ownership.

## When an effect is visible

Time and weather use an opt-in adapter for the verified Homesickness x86 renderer ABI. Unknown clients and the synthetic preview can configure the values but do not apply native overrides. Startup discovery finds unique executable instruction anchors and follows relocated in-image operands to the application vtable, clock, sky, player and weather option. It checks the frame gates, methods and memory protections before installing reversible vtable hooks. FPS, environment overrides and the D24 presentation policy share this cached layout. File hashes, timestamps, entry-point RVAs and the old image size are not compatibility gates; resource-only updates and relocated compatible code/data remain supported. Changed or ambiguous function signatures disable the affected adapter rather than guessing. This is not a guarantee for arbitrary compiler or structure-layout changes. Discovery is read-only, runs once and releases its temporary section snapshots. It temporarily substitutes the visible clock fields and precipitation data only during rendering, restoring the game's clock, weather selection, particle history, option and texture ownership afterwards. Network state, server clocks, dates and simulation remain native. Rain/snow use the client's artwork and bounded native particle capacity, with a separate local animation history. Maps with custom or fixed environments may limit the result. Settings are stored in `[Environment]`; old configurations retain native time and weather.

Sun Rays need daytime directional illumination near the camera's view and sky gaps interrupted by geometry; pointing down at night is not a useful comparison. They do not create light shafts in every scene. SkyFX now recognizes the actual night skybox03/cloud03 passes from the supplied capture, which the earlier day-only catalog missed. When an enabled effect lacks a supported sky, light source or scene depth, its expanded controls show that condition rather than silently suggesting a working effect.

Foliage gaps in water reflections are a limitation of the current screen-space reflection path: the main camera's depth/color does not contain hidden crown undersides or off-screen branches. Fine leaf silhouettes can also fail depth-hit validation. A detailed underside in the original model is insufficient without a separate reflected-camera geometry pass. This update does not claim complete planar reflections or fill those gaps with invented tree geometry.

Water reflection tracing now has a separate material pass over the same native water geometry. It validates depth continuity using independent one-sided extrapolations on both screen axes, accepting the continuous side at a low-poly crease instead of cutting a wire-shaped gap along every change in slope. Reflected backface and initially occluded hits remain rejected. Unsupported hits use the sky environment. Object reflection coordinates follow the geometric surface; animated ripple shading, refraction and glints remain enabled. Object Fresnel is filtered toward the macro surface so small ripple normals do not cut bridges into strong light/dark stripes. The extra RGBA8 target costs four bytes per viewport pixel and is released when tracing is inactive. Each shader stays within the Shader Model 3 instruction limit.

**Lighting balance** provides bounded ambient fill before shading common lit opaque fixed-function materials, including supported props and weapon paths, without an object-name whitelist. Daytime material lighting is preserved. A second, hue-preserving contrast curve covers the entire world image, including programmable/skinned and unlit paths. Its pivot follows GPU mean log luminance through independent FP32 history, lifting dark detail and restraining unusually bright models. Gain is bounded, zero intensity is neutral, and black pixels remain black. Reduction targets are shared with brightness adaptation; only two tiny scalar histories are added, with no extra full-size image target or CPU readback. It cannot recover detail already absent from the source color. The two mechanisms are controlled by the same independent section; ordinary exposure remains separate.

Shallow water retains its optical surface: shore softness acts on a narrow edge and retains a small surface response instead of suppressing it across a broad shallow band. A restrained minimum optical layer covers valid horizontal water pixels even when the sampled floor is nearly coplanar; water deeper than 0.35 world units retains the original absorption path. The original water mesh, depth testing and texture cutouts define coverage, so the minimum layer does not paint the dry background outside that mesh. Absorption coefficients are prepared on the CPU once per material replacement rather than evaluated logarithmically per pixel.

## Scene rendering, lighting and antialiasing

Scene processing runs at the existing pre-HUD boundary. Camera matrices and the viewport come from the first compatible main-scene opaque draw. Orthographic shadow passes, other render targets, unsupported projections and later 3D portraits cannot supply this camera. Spatial effects retain the depth surface bound with their main-world camera and copy that surface even if a later UI/marker pass binds a different depth buffer. They use a separate GPU depth snapshot through the same optional NVIDIA path as WaterFX; FXAA, SkyFX, exposure and vegetation fill do not require that backend. Unsupported depth leaves the affected effects inactive rather than inventing geometry.

- **SSAO** reconstructs view-space receiving positions and normals, samples a bounded world-space radius with 8 or 16 directions, fades with distance and uses depth-weighted upsampling. Receiver normals use the spatial-field footprint and snapped depth sample positions, avoiding false horizontal occlusion bands on unoccluded slopes. Exactly identified native Kaillun/Upresia grass cards retain native color, alpha blending and depth testing during proximity fades, with depth writes disabled for their translucent draws while SSAO is active. These cards no longer replace the ground depth with rectangular AO receivers/occluders; unblended cutout draws retain their depth writes. Render state is restored after each draw. Unknown textures and programmed geometry remain native. It is contact occlusion on visible geometry, not new world shadow maps.
- **Sun Rays** projects the enabled directional light and integrates a sky/depth occlusion mask at reduced resolution. The source uses actual bright sky radiance rather than an artificial luminous spot: a strong game light over a dark sky cannot create a giant disc. A 4×4 area filter resolves subpixel sky gaps before 48/64 linearly filtered radial samples. Source and ray fields use FP16 to avoid coarse 8-bit bands; decay is normalized across quality tiers. The two fields cost approximately 1.85 MiB together at 1920×1009 in economical mode, or 7.39 MiB in detailed mode, and release when disabled. Foreground geometry can interrupt the light. These are screen-space crepuscular rays, not a world-volume simulation; off-screen occluders cannot be recovered.
- **SkyFX** changes only exactly identified sky/cloud passes. It preserves native texture-stage RGB/alpha operations and supported 2D texture-coordinate transforms, including cloud scrolling. The native sky art supplies day/night brightness; a luminance-preserving atmospheric tint modifies blue regions while retaining cloud and star detail. Cloud contrast keeps the original alpha. The directional daytime halo remains independently adjustable. This avoids multiplying SELECTARG1 texture color by unrelated vertex RGB or darkening the sky with object diffuse lighting. Sky detail reconstructs magnified sky/cloud texels with a bounded nine-tap Catmull-Rom filter; it does not create new high-resolution cloud artwork. Night processing suppresses coarse star blobs and adds procedural fine stars anchored to sky directions. A screen-footprint Gaussian keeps these points round and antialiased as the camera rotates. Native daylight fades the new stars; gray cloud silhouettes in the panorama mask them, and cloud-only passes cannot receive them. The exactly identified cloud03 star/nebula overlay is treated separately from real clouds: sky detail suppresses its large star blobs while retaining the native UV animation. Regular cloud scrolling and all native RGB/alpha fades remain intact. Sky detail at zero retains native texture sampling; Fine stars controls their brightness. The same material replacement participates in water cubemap capture, needs no additional texture or render target, and retains native day/night/weather transitions.
- **Fog** adds distance and height-dependent atmospheric extinction to visible opaque geometry. Height density uses the midpoint of the camera-to-surface segment. With an identified sky, a GPU reduction of low-elevation directions in the shared sky-only cubemap supplies world-space horizon radiance, independently of camera yaw and the zenith color. Unrecognized sky paths retain the diffuse scene-sky average fallback. Resolved silhouette color receives coverage-weighted retinting instead of full opaque-pixel correction, avoiding bright outlines. Clear-depth sky pixels are never reclassified as geometry from their color, preventing moving sky glows/cloud strips from becoming phantom fog surfaces. The native linear fog contribution is retinted in its display-color composition space; additional extinction supplies only the difference between requested and existing opacity. This avoids attenuating native terrain detail twice. Zero density leaves native fog unchanged. Moon and cloud texture details are never projected onto foreground surfaces. Color controls tint the intermediate haze without creating a separate far-color wall. This does not extend native draw distance, recover culled terrain or undo native fog already present in the input. The optional full-size sky snapshot costs four bytes per viewport pixel, plus approximately 2 KiB for its 16/4/1-pixel FP16 reduction chain. The 384 KiB sky cubemap is shared with WaterFX and can be captured for fog when water is disabled; there is no CPU image readback.
- **Depth of Field** uses manual focus distance, a sharp range and a 16/32-tap linear-color gather in a separate pass. Defocused foreground contributes smoothly across sky silhouettes according to its own circle of confusion; focused foreground keeps its sharp edge. Bright sky pixels no longer bypass filtering as if they were emissive particles. The pass reuses the consumed world snapshot as its output, adding no full-size texture. Near blur has its own strength. Bright image features retain their sharp cores through a conservative brightness heuristic; this is not a separate particle-depth layer. It is intended as an optional cinematic control, not physical aperture simulation or character tracking.
- **Brightness adaptation** reduces mean log luminance through 64/16/4/1-pixel GPU targets and smooths a persistent FP32 EV value with separate bright/dark rates and limits. FP32 history avoids quantization stalls at high render rates. The pre-HUD scene supplies luminance. There is no production CPU image readback. Disabling adaptation or resetting the device releases/resets its history.
- **Night vegetation** identifies the common tree texture families by exact first-mip identity and adds bounded ambient fill only during their compatible fixed-function draws. Original material and ambient state are restored immediately. Directional illumination, alpha cutouts and textures remain native. A daytime fixture verifies unchanged output. Unknown foliage families are left alone.

**Local surface illumination** supports up to eight native point lights and 32 recognized emissive draws. Each emissive draw is replayed into its own 32x32 UV-space tile, then reduced to a source position and radiance. The atlas stores positions relative to a stable world origin rather than screen bins, so camera rotation and projected size do not move or duplicate a lamp. Recently observed sources persist for up to 0.5 seconds with a short fade when native culling stops submitting them. Native vertex color, texture factors and alpha fading are retained for supported simple texture stages. Unknown, programmable and complex passes remain unchanged.

Emitter slots match material and nearby world anchors rather than transient vertex buffers or exact floating-point bits. Halo layers around one bulb share a slot. The cache retains up to 32 spatial sources, prioritizes nearer candidates with distance hysteresis, and permits at most 96 capture draws per frame so early distant halos cannot consume the entire discovery budget. This bounded cache cannot illuminate a source the client has never submitted; briefly missing sources retain the existing half-second fade.

Receiver normals use neighboring samples on the same depth surface; the light field is upsampled from its actual texel centers with depth rejection. A neutral regularization term fades weak depth matches instead of amplifying a nearly unrelated field sample into an isolated bright pixel. Bounded reflectance recovery and a soft per-channel lighting response let a dark receiver brighten without hard additive clipping. A small finite-source angular approximation softens the near-light terminator; it does not reconstruct smooth mesh normals or real area-light shadows. The old sparse screen-space shadow march has been removed: its discrete blockers stamped shifted character silhouettes into the scene. These additional lights are **unshadowed** until a reliable light-space geometry pass is available, so walls can still leak light. This is not full albedo reconstruction, shadow mapping or global illumination. Emitters not previously submitted by the native renderer and hidden receiving surfaces remain unavailable. Capture and reduction stay on the GPU without production image readback or retained game geometry.

Known native `lenzflare_001` through `008` material passes use a smooth analytic warm halo under SkyFX. Exact texture fingerprints and the captured depth/blend state restrict the replacement to the native flare path; ordinary particles, lamp glow and HUD materials retain their original rendering. Native quad placement and vertex fading remain in control. **Sun halo** controls its strength along with the directional sky halo.

The **Materials** tab contains **Surface appearance**, **Relief**, **Snow** and the independent image **Microcontrast** control. The surface switch is in the Surface appearance heading and is opt-in (`materials=0` by default). Section descriptions are available on hover instead of repeated paragraphs in the parameter area. `material_strength`, `material_relief`, `material_glints` and `material_snow` range from zero to one and default to `0.75`, `0.6`, `0.35` and `0.75`. The appearance reset restores these parameters without changing the switch. Existing image-detail keys retain their values and are available under Microcontrast.

Surface material shading uses the original static world texture and native geometry in a single draw, with no extra render target or replacement artwork. Exact uploaded-texture SHA-256 identities recognize snow, stone, wood, sand, ground/grass, bark and snow-covered vegetation. The catalog covers 144 original texture files, including nine inspected tree-bark textures (eight Azria bark atlases and GiantTreeBark) and 20 winter foliage/branch atlases; names alone are never used at runtime. Visual review separates snow (`ground_n_ice02/03`) from the similarly named icy paving and dirt assets. Unknown uploads, characters/skinning, particles, alpha-tested meshes other than exactly identified bark/winter vegetation, unsupported stages, custom shaders, clip-plane passes and later HUD/portrait draws remain native. Support is deliberately bounded; this is not an automatic physically based conversion of every material.

Material shading now uses a pixel-only Shader Model 2a path with the native fixed-function vertex converter. World/view/projection transforms, vertex shaders and constants, FVF/declarations, input streams, index buffers and native depth calculations remain untouched. Replacing the native vertex shader changed quantized depth on large absolute world coordinates, causing coplanar terrain layers to fail their depth tests. Keeping native vertex processing preserves the original layer ordering and coverage, including mixed styled and unstyled draws. It also retains native material/ambient, directional and point lighting. Up to three simple fixed-function texture stages are reproduced in the pixel shader, including the terrain blend map and projected mask. Disabled stages terminate the chain.

Two otherwise unused coordinate outputs provide native camera-space position and normal for restrained, source-gradient relief and view-dependent highlights. Their coordinate-generation flags, texture matrices and wrap state are captured and restored per draw, along with pixel constants and fog state. The original fog curve is evaluated per fragment; native fixture parity allows one or two RGB levels for interpolation and MSAA rounding. Stone, furniture wood and bark use bounded texture-gradient relief, with four diagonal samples smoothing the gradient across its other axis. Bark uses a separate pixel-shader variant: a positive LOD bias and a dedicated trilinear sampler filter its height estimate toward a coarser source mip, while the visible artwork retains its native sampling. Relief follows the grain direction with a weaker cross-grain slope, avoiding hard per-texel terraces. The source sampler's addressing and sRGB interpretation are preserved. Single-mip uploads use a softer spatial-gradient fallback. No synthetic fiber noise is added, and the painted snow skirt within the known atlas is preserved. Snow additionally samples a cached, generated 128×128 detail map with eight mip levels (85.3 KiB). It stores bounded gradients of fine angular grains, correlated albedo variation and an independent crystal seed. A short periodic neighbor filter gives each grain a coherent light response without large rounded height-noise blobs. Detail is anchored in material UVs, filtered with mipmaps and faded by its pixel footprint. Snow uses a finer, weaker grain field and sparse light-dependent crystal glints; its broad continuous material highlight is disabled. At full snow appearance, painted mottling no longer becomes a bump map; source luminance contrast is reduced to 45 percent and gently lifted instead. A restrained cool-white tint is shared with painted tree snow; native day/night lighting remains active. No extra draw, render target, texture-file replacement or UV displacement is added. Sampler 3 and its texture/filtering state are captured and restored alongside the spare coordinate outputs. Snow color correction retains a reduced version of each source pixel's luminance pattern with a cool neutral tint. Zero strength uses the untouched native draw. Identities remain cached on the original resource and invalidated by the existing texture-write hooks.

Regenerate the identity header with `node tools/material-catalog.mjs`. An optional client-directory argument verifies the original files read-only. Native fixtures cover fixed-function parity, lights, fog, transforms, three texture stages, state and input restoration, following native draws, zero/off and resource recreation. Coplanar depth tests use synthetic large world coordinates, D16/D24, buffered/UP draws, projected masks, fog and zero/8x MSAA. Maximum-strength snow tests check compressed but retained luminance detail, bounded close-up grain lighting, minification fade, changing directional light and deterministic detail-resource recreation. Bark tests cover the mip-filtered shader and single-mip fallback, a bounded maximum response, native alpha-test coverage, coplanar depth and sampler/texture restoration. Winter foliage uses a separate pixel-only variant controlled by the same Snow appearance slider. Only bright, neutral/cool regions inside the exactly identified winter atlases receive the ground snow tone; green needles and warm branches remain native. Bark snow skirts use the same painted-snow mask. Foliage receives no procedural bump grain, bark relief or broad highlights. Original alpha tests and standard alpha blending, including depth-write-disabled foliage, remain in control. Plain green seasonal variants are excluded. Synthetic fixtures verify snow/green/bark isolation, neutral parity, native alpha/depth coverage, fog, blend and state restoration with and without MSAA. The local `material-test --assets <client-directory>` fixture renders original snow, stone, wood, sand, grass, Azria bark, snowy needles, canopy and branch textures in controlled close and wider views, including relief-zero captures; these are not live Azria captures. Live-client motion, texture-family coverage and GPU/FPS cost still require validation.

The **World → Grass** page controls opt-in instanced 3D vegetation. Coverage exposes quality, distance (5–100), density, maximum slope, distance fade and a separate Snowy grass switch (`grass_snow=0` by default); separate pages control blade height (0.1–1.5), width and variation, wind strength/speed/direction, and brightness/saturation/dryness/base shading. Compatible `[SceneFX]` keys use the `grass_` prefix, with `grass=0` by default. Parameter resets preserve both grass switches, language and other grass sections. Snowy grass uses the same shape, density, distance and wind controls, with a restrained neutral-white palette. Identified snow ground marks the verified native world as winter terrain, so recognized grassy/mixed-soil seams cannot leave green clumps in Azria. The marker resets on a world change; unsupported hosts classify each frame independently. Icy paving is excluded. The standard default stays off; Default (High-end PC) enables green and snowy grass at high quality, distance 55, density 1.5, height 0.6 and a broad 0.4 distance fade.

Native fixed-function terrain is replayed into a local world-space RGBA32F map containing height, coverage, geometric slope and ground luminance. Exact identities in `tools/grass-materials.json` distinguish 19 lawn/Kalilun/Rartesia/Rustia and mixed-soil ground textures, two snowy ground textures and two native grass-card textures; unknown terrain layers erase grass through their native coverage, while compatible props contribute to a separate ground-contact height map. Exactly identified foliage cards never erase ground coverage, including opaque proximity states. Native alpha-test state left by foliage cannot exclude a terrain layer. Props use authored texture alpha, independently of camera proximity fade; the lowest captured surface blocks roots only when close to their ground height. Elevated roofs and canopies therefore do not erase the lawn below. Unknown road layers write only coverage/slope, never ground height. The native geometry/depth draw remains unchanged. Bilinear footprints reject road/prop boundaries and discontinuous height levels. Blended receivers write height separately and discard zero coverage so an invisible layer cannot move the receiver. GPU-backed commands reuse a fixed pool of 256 records and are flushed before native resource writes; UP commands remain immediate. There is no whole-frame draw-count cutoff: native shallow camera views can exceed 2,048 terrain passes, which previously discarded all accumulated grass. Both one-UV rigid ground and two-UV terrain can initialize the map when their texture is exactly identified. Five inspected grass/soil atlases use source-color coverage restricted to those identities, keeping warm bare dirt free of blades. Capture sampling uses artist RGB and a world-map mip footprint instead of inherited native sRGB/mip settings; no global color-based material guessing is used. No CPU terrain readback or collision modification is used. The terrain and R32F contact maps together cost 1.25/5/20 MiB at low/medium/high quality (256/512/1024 squared), plus bounded static mesh and instance buffers. The map origin snaps to its world texel pitch. Three distance bands use nested root grids at spacing factors 1/2/4: surviving roots retain their location and height, while other roots shrink gradually before each boundary. Distant ribbons use fewer segments and continuously wider blades. Each blade samples its own planted base, including its offset within the clump, so smooth steep terrain does not bury or suspend the outer blades. The map, LOD rings and distance fade follow the verified native player position; camera position remains separate for fog and screen-size compensation. Unsupported hosts use the camera fallback. Root grids and variation are anchored in world coordinates; wind leaves roots pinned. Height, width, wind and color changes update shader parameters without rebuilding the mesh.

Grass renders against native world depth before the first HUD draw and before image post-processing. Native transforms, declarations, stream frequencies, sampler state and targets are restored. Mixed vertex processing temporarily uses hardware for the additional geometry and restores the host mode after its bindings. Image **Microcontrast** combines fine-detail enhancement with a wider, edge-aware local-contrast band. The wider band gently emphasizes existing painted shading and surface patterns instead of only outlining one-pixel edges. Its diagonal samples reject large luminance discontinuities to reduce halos across silhouettes, while near-flat noise and extreme tones are suppressed. The wider band uses 3.5-pixel diagonal offsets with a restrained response, retaining the same eight neighboring samples. The luminance correction is limited to 0.045 times strength, with a small allowance beyond the neighborhood extrema, to preserve soft midtones when combined with surface shading. These limits apply to existing saved strength values as well; no configuration migration or reset is needed. ## Native client frame pacing

The FPS option installs the verified application's `FrameMove` gate before releasing its native render limiter. The full hybrid adapters discover code and data from normalized instruction probes, verified native RTTI/vtable ownership and checked call/global relationships. Their reference RVAs are IDs rather than assumed live addresses. The complete dependency set is validated before the first patch; relative calls and continuation jumps are rebuilt for the discovered locations. Missing or ambiguous matches, changed instructions, incompatible section access or broken dependencies reject the full adapter before installation. No file hash, resource timestamp or uniform relocation delta is used. Discovery snapshots are temporary; installed callbacks retain resolved pointers. Subsequent activations revalidate the cached locations. When all native adapter signatures match, the hybrid loop advances movement, animation, held input, SFX followers and camera work using elapsed wall time. Continuous world updates use bounded substeps, while counters and legacy services retain their original 16 ms cadence. Long pauses reset the timing history instead of replaying a loading screen. If the additional native adapters are unavailable, the fixed 16 ms simulation fallback retains native actor positions, rotations and world matrices. It does not hook mover processing or rendering: extrapolating geometry independently of shadows, selection, range checks and skill origins causes gameplay misalignment. Camera smoothing and animation sampling remain available. Sampled animation frames, blends and bone storage are restored immediately when each model draw returns, including repeated passes; native render-time clip changes and replaced bone storage are preserved. Native positions still advance at the simulation cadence in this fallback. The camera and animation adapters discover their verified functions, vtable ownership, active-player slot and camera vectors structurally, so a client rebuild can move them without silently losing all smoothing. Ambiguous tables and incompatible instruction layouts remain rejected. This does not establish compatibility with arbitrary compiler or structure-layout changes.

Enable **Unlock FPS** in the panel footer, or set `unlock_fps=1` under `[General]`. It is off by default, independent of the effects switch, and preserved when changing image presets. Frame-gate discovery uses structural checks rather than a whole-file hash. The additional native adapters verify their expected instructions and data layout before applying reversible in-memory call and operand patches; incompatible adapters are rolled back. In full hybrid mode the player and remote movers advance their authoritative positions on every positive render interval, including intervals with zero legacy ticks. Mover rotation, translation and world matrices are published before class-specific SFX followers refresh, so rendering and effect origins use the same state. There is no previous-frame position buffer or render-only actor prediction in this path. The 16 ms unit remains for legacy counters, hit-stop duration and effect lifetime rather than gating continuous movement. No EXE file is modified. Disabling the option or releasing its last owner restores the native patches, vtable and limiter flag. Driver and VSync limits still apply.

## WaterFX implementation and limits

WaterFX replaces the material only for the two water texture families identified in the Homesickness Neuz render capture. Identification uses exact first-mip SHA-256 fingerprints, cached as texture-private metadata. The draw must also match the observed fixed-function layout and transparency state, belong to the main backbuffer and occur before the HUD. Unknown textures and unsupported states retain the original renderer. No game memory or vertex-buffer readback is used.

The material supplies animated wave normals, two drifting and rotated normal-map layers, adjustable opacity, a turquoise tint, GGX directional-light glints and Fresnel reflection. **Neuz mesh positions are preserved:** the wave-height control changes shading normals without lifting independently drawn tiles or river skirts. No geometric displacement or tessellation is added. Camera-relative interpolated positions keep geometric derivatives stable at large world coordinates. A deterministic 32-wave spectrum generates a single 128-pixel normal texture with a complete mip chain once. The original water texture RGB remains a separate, low default contribution; texture alpha preserves cutouts. Ambient light, material properties and the enabled directional light illuminate the water body. The analytic sky fallback follows that illumination at night.

Opacity is controlled by FENB and texture cutout coverage. Legacy vertex and material alpha are not multiplied into it: a zero vertex alpha channel previously made the material almost invisible and defeated the opacity control. The native water regression fixture now uses zero vertex alpha and verifies that both opacity settings still produce distinct visible results.

Refraction uses a GPU-only color snapshot taken once before the first matched water draw in each frame. It does not sample the live render target or recursively refract previously drawn FENB water. With valid depth, the material computes the optical path between the water surface and opaque scene, applies channel-dependent absorption, softens the shoreline and fades fine normals at contact. Refracted samples above the water plane or in front of its surface are rejected. Without valid depth, it retains uniform transparency and conservative distortion; foreground color leakage is still possible in that fallback. Only geometry already drawn before the snapshot is available.

Sky reflection captures the exact identified `skybox01`–`skybox06`, `cloud01`–`cloud05` and `rartesia_cloud` families, including low-resolution versions. It replays their fixed-function geometry into a 128-pixel cubemap, updated at most four times per second. The refresh decision is latched on the first sky draw and the faces are cleared only once per frame, preserving every subsequently blended skybox/cloud layer during day/night transitions. A failed face invalidates that refresh instead of publishing a partial map. Only their original DrawPrimitive calls are repeated, with six camera orientations, the original texture stages and no depth buffer; no world scene is replayed or retained. The water samples this actual sky/cloud rendering with its reflected normal. Unknown sky textures or unsupported paths use the analytic gradient. A frame without a matched sky cannot reuse a stale map from another scene. The native fixture verifies the capture, cubemap selection, main-target preservation and state restoration; appearance in the live client still needs checking after restart.

Depth-based optics currently use the optional NVIDIA driver path: registered D16/D24 scene depth is copied into an INTZ texture through [NvAPI_D3D9_StretchRectEx](https://docs.nvidia.com/nvapi/group__dx.html). The native fixture verifies actual sampling of the resolved depth and rendering with both D16 and D24 at zero and 8x MSAA. The copied source remains the actual depth surface used for scene rendering. Driver functions are loaded only from the system directory; no NVAPI redistributable is required. Unsupported drivers, formats, projections or failed copies use the fallback material. RESZ support alone is not assumed.

Water and scene effects keep separate snapshots because their capture boundaries differ. They share reference-counted NVIDIA API and resource-registration ownership: disabling or destroying one consumer must not unregister the other's live game depth surface. A native regression repeatedly toggles and destroys both consumers, then resets the device, for D16/D24 with zero and 8x MSAA.

SSR traces the copied opaque depth with 24 or 48 steps, a fixed 512-world-unit distance cap and twelve bounded refinement iterations. The former 80-unit cap omitted visible banks in the real river capture. A candidate is refined against a local affine perspective-depth plane using texel-centered samples and stable one-sided gradients, rather than accepted at the nearest-depth texel stair step. At a rejected candidate, a one-texel cross checks up to four adjacent local planes against the same physical ray and copied depth. A rejected silhouette no longer terminates the entire search: later depth crossings remain eligible. Projection/reconstruction includes the DX9 half-texel convention. Quantization has a flat acceptance range before confidence fades, avoiding stippled brightness on a continuous diagonal bank. The refined hit must remain within the local source footprint, match its depth, face the reflected ray and lie above the water plane; clear-depth sky is rejected. A source-facing confidence term rejects nearly edge-on planes spuriously fitted across foreground/background depth jumps, which otherwise stretch leaf colors into streaks. Degenerate intersections are rejected before projection. For every accepted hit, a bounded 3×3 color reconstruction checks that each tap's depth and four-neighbor footprint agree with the same source face, using a tighter tolerance than geometric hit acceptance. This avoids using foreground-leaf MSAA color coverage for a background-bank depth hit. A fully supported source footprint retains the original bilinear color output. The native regression checks actual mirrored leaf geometry during camera yaw and subpixel motion, in local and baked large-world coordinates, at both SSR quality levels and D16/D24 with zero or 8× MSAA. The reflection target is cleared to zero confidence once per frame. Its ray begins on the actual water surface, advancing along the ray instead of shifting the mirror plane along its normal. Animated wave normals remain independent: accepted world-color samples receive no additional screen-pixel warp, while waves still change lighting and Fresnel strength. Steep skirts suppress reflection, refraction distortion and specular glints. Refraction rejection tests the local plane in view space, including sloped river sections. Missing hits fade to the sky environment. These changes add no texture, render target, pass or production readback; accepted-hit shading does more local work, particularly at silhouettes.

SSR still sees only visible, previously rendered geometry: off-screen objects, hidden surfaces and later transparent passes cannot be reconstructed. There are **no complete planar world reflections or reflection scene replay**. D16 precision, screen-space disocclusion and defects already present in the source geometry can still produce artifacts; stability tests are not proof that every map is seam-free. Sun glints use the enabled directional light. Full dynamic shadow maps remain separate work.

The optional **24-bit water depth** action (`precise_water_depth=1`, enabled by default) upgrades only an automatically allocated D16 buffer in the pinned Homesickness client, at CreateDevice/Reset. Format, depth-stencil and the existing MSAA quality are checked before use. Allocation failure retries the original D16 parameters; Lost Device is propagated. Color format, dimensions and MSAA are unchanged. The option requires a client restart. It adds roughly 32 MiB of driver depth storage at 1920x1080 with 8x MSAA; actual driver allocation may differ. Distant shallow-water stripes may come from D16 precision, but fixing every reported beach artifact is not yet live-verified.

Optional caustics reconstruct receiving positions and normals from copied opaque depth and evaluate refracted directional-light focusing in a separate reduced-resolution pass. A finite-difference ray-map Jacobian gives bright and dark concentration patterns, with a small wavelength-dependent IOR variation controlled by **Dispersion**. The field is sampled only by underwater transmission; SSR reads the unchanged scene snapshot. Focusing uses an approximate two-world-unit slab rather than a full ray trace through arbitrary water geometry. Real optical path length fades the result; directional light controls day/night strength. Flat normals produce no patterned focusing. This is not volumetric scattering, light-occlusion tracing or a generic RGB screen filter. The main profile retains the active water configuration with caustics disabled; the parameter remains independently adjustable.

Color and depth optics need one full-size 32-bit color target and one INTZ depth texture, copied at most once per water-containing frame. Together with the 384 KiB sky cubemap and 85 KiB normal mip chain, this is about 15.2 MiB of owned GPU resources at 1920×1009 before the optional caustic field. Enabled water SSR uses a trace target (RG32F) and a premultiplied color/confidence target (RGBA8), together 12 bytes per pixel at the selected reflection resolution. At 1920×1080 this is about 23.7 MiB at 100%, 13.3 MiB at 75% and 5.9 MiB at 50%, excluding the shared full-size scene/depth snapshots. Two bounded water-geometry replays separate intersection and radiance validation within the Shader Model 3 limits; accepted face anchors survive both passes, preventing a refit onto foreground leaves. Color retries stay local to that face neighborhood; a confirmed near intersection with unsupported color falls back to sky instead of searching a farther object. Premultiplied confidence allows linear filtering without dark seams. Disabling object reflections releases both targets. The field adds about 0.46 MiB at quarter dimensions or 1.85 MiB at half dimensions and one pass per water-containing frame. There is no CPU image readback or persistent copy of game geometry in production. Zero refraction, absorption, SSR and caustics together release the color target; zero absorption, SSR and caustics release the depth texture; zero sky contribution releases the cubemap. Normals retain their small managed texture until Reset or teardown. The pixel shader fits the 512-slot Shader Model 3 budget. Resources are released for Lost Device/Reset and recreated lazily. Native fixtures check object reflections, shallow/deep transmission, caustic receiver isolation, day/night strength, flat-water neutrality, both field resolutions, resource release and restoration; they do not establish live FPS cost or visual parity with another game.

The stability fixture also compares zero and maximum wave amplitude: reflected-object support must overlap by at least 90%, and a constant-color rendering of two water levels joined by a vertical skirt must remain pixel-identical. Diagonal-bank checks count interior holes and abrupt confidence changes under subpixel camera shifts, both quality tiers and translated coordinates. A color-ramp wall checks reflected source coordinates against the analytic mirror, and a separate foreground object checks that reflections remain inside its analytic bounds. Fixtures run at the origin and near world coordinates (7000, 100, 3300), with D16/D24 and both non-MSAA and 8x MSAA paths.

Restoration also preserves the input-binding changes required by [DrawPrimitiveUP](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-drawprimitiveup) and [DrawIndexedPrimitiveUP](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-drawindexedprimitiveup). Native regression tests exercise both paths.

Post-processing runs at the first accepted RHW UI draw or an exactly recognized native 3D quest-marker draw after confirmed depth-writing perspective geometry. The marker boundary precedes its native draw: a transparent arrow can still write depth, which must not become a phantom surface for fog, DoF or ambient occlusion. Recognition combines the captured small fixed-function mesh layout, alpha/blend state and cached first-mip identities generated by `tools/emitter-catalog.mjs`; ordinary world objects are not classified from material alpha alone. The marker's visibility, native material and depth state remain unchanged, including when its real quest UI is visible. Opaque HUD colors remain exact. Translucent HUD backgrounds keep native alpha compositing over the processed world and therefore naturally change with that world. A full-viewport main-target color clear starts a new render epoch even within the same Present interval; partial clears and off-screen targets do not. Sky geometry, depth-disabled 3D markers, pre-world RHW passes and depth-tested or color-suppressed visibility probes cannot latch processing off for the rest of the frame. Screen-space-only UI frames and late orthographic portraits remain excluded from the Present fallback. Present and swap-chain Present remain supported. Color/depth resolves and full-screen passes neutralize user clip planes, the multisample write mask and texture-coordinate wrap under the existing state guard.

## Build and checks

The local portable LLVM-MinGW toolchain lives under `.tools/llvm-mingw-*-ucrt-x86_64`. Run `./build.ps1 -Tests`, `./dist/FENB-preview.exe` and `node tools/verify-binary.mjs`. The test build checks settings, exact HUD colors, native water material selection and restoration, transparency, Reset, input handling and panel interactions. The water fixture test reads the locally installed DDS; it reports a skip when that optional game asset is absent. Test screenshots and configuration files stay in ignored build folders.

Use `-Diagnostics` only for the opt-in bounded pipeline capture. The normal build has no capture code. The diagnostic menu delays a three-frame capture by three seconds so the panel can be closed and a wake or splash reproduced. Native rings and splash particles are still rendered by the game; their draw states must be captured before integration. A CMake x86 build is also described in `CMakeLists.txt`; the PowerShell/LLVM build is the verified local path.

Surface reflections also record up to three native-resolution lower-center crops (at most 960 by 640 pixels each) when a diagnostic `FENB-surface.request` marker beside the DLL starts a surface capture. Water replay payloads are excluded in this mode so they cannot exhaust its budget. Each frame contains color before/after the surface pass, the raw floating-point material/receiver mask, R32F copied depth and all 61 pixel constant registers, including the native depth quantization controls in c60. The surface-frame record declares its `uniformRegisters` count and `maskFile`; masks may be FP16 in older captures or FP32 in current captures. c60 also includes the transform-roundoff allowance. Image records preserve crop origins and source dimensions for reconstruction. These records share the existing 64 MiB replay budget, omit the HUD and add no readback or capture polling to normal builds. They diagnose receiver rejection and compositing independently of later atmosphere and color processing. Run `node tools/inspect-surface-reflections.mjs <capture directory> <ignored output directory>` to export before/after, amplified differences, material coverage and receiver-validity bitmaps plus a JSON report. Legacy 60-register bundles remain viewable, but receiver validation requires c60 and reports itself unavailable when those controls are absent. Receiver validity does not identify the SSR hit or explain flicker by itself.

Diagnostic schema 2 also records a replay bundle from the first captured water frame when WaterFX is active. `water-color.argb` is the original pre-water scene; `water-depth.r32f` contains the copied depth values without an 8-bit conversion; `water-reflection.argb` is the computed reflection and confidence; `water-final.argb` is the world image at the pre-HUD boundary. `water-image` records give dimensions and DX9 formats. Up to 32 recognized nonindexed water draws include topology, viewport, VS/PS constant blobs and FP32 native positions. For GPU-backed draws, a diagnostic point pass extracts positions from the actual vertex stream, including its byte offset and first vertex, without reading or locking native write-only buffers on the CPU. Position grids have up to 256 columns; only the recorded vertex count is used. Native UP data is copied within the intercepted call. The water payload is limited to 64 MiB, separately from the existing draw-log budget; truncation is reported. Temporary GPU targets/readback surfaces are released immediately and CPU blobs are released when the three-frame capture finishes. Capture can briefly stall rendering. The bundle contains graphics data only and has no production-build overhead. Version 0.3e adds this evidence path; it does not claim that the live reflection defects reported after 0.3d are fixed.

`node tools/water-catalog.mjs <World/Texture directory>` regenerates the checked-in exact water fingerprints. Proxy interfaces are generated with `node tools/generate-proxies.mjs <d3d9.h>`; do not hand-edit generated forwarding methods.

`node tools/emitter-catalog.mjs <client directory>` regenerates emissive and common-tree material identities. `tools/emitter-decoded.json` also records verified ARGB8 upload identities, guarded by the compressed source hash with case-insensitive asset names. This includes the captured `sfx_light02` and `obj_GenLight01` uploads rather than only their compressed DDS representations. The optional offline `tools/texture-fingerprint.cpp` helper uses system D3DX9 to derive such identities; D3DX is not a production DLL dependency and no game textures ship in this repository.

Local-light source positions use a camera-near FP16 atlas origin. Moving more than 256 world units from that origin invalidates the previous source history and rebases the next capture, including after distant map teleports; this does not require toggling the effect. Exact known Flaris window, quest-office, machinery and sign light maps can supply emission, including verified ARGB8 uploads and native texture stages that only forward CURRENT unchanged. Registered static windows and world lamps retain sources for up to five seconds, with a final half-second fade, across short native visibility gaps. Transient glow sources retain their previous 500 ms lifetime; toggling local lighting, Reset and map rebasing clear both kinds. Other multitexture operations, lit/opaque geometry and arbitrary bright textures remain excluded. These sources illuminate depth-reconstructed scene surfaces as unshadowed local lights; this is not a replacement for light-space shadow maps.

Optional surface reflections use exact paving/stone texture identities from `tools/surface-materials.json`, generated with `node tools/surface-catalog.mjs <client directory>`. These include the captured current Flaris plaza model atlases and the decoded TGA upload used by its yellow road paving, as well as DDS terrain paving. Source-file checksums guard both formats; non-DDS files are never parsed as DDS headers. The central plaza atlas's planter-grass UV region is excluded explicitly; brightness or green color is not used to guess materials. Rigid fixed-function ground geometry supplies a full-size FP32 mask with material reflectance, texture-dependent roughness and camera-relative receiver height. GPU-backed mask draws are replayed in bounded batches of at most 256 retained commands, with one state guard and target switch per batch. UP data remains immediate. Buffer and texture write locks, updates, copies and GPU vertex writes flush pending commands first; render-target blend coverage uses the immediate path. This avoids a full DX9 state capture and target switch for every unrelated terrain layer without discarding grass coverage. Native two-UV terrain blend coverage erases reflectivity beneath unknown/grass layers. Mask alpha accumulates coverage using separate alpha blending; the completed pass divides weighted roughness by that coverage, while reflectance keeps its native layer weight. Receiver height never participates in material blending: opaque draws write all channels directly; blended draws replay their height into the same mask with blending disabled and only the height channel writable. Zero-coverage fragments are discarded in both replays, so invisible layers cannot replace a visible receiver. This adds a geometry replay for blended layers without another target or full-screen pass. Spatially varying terrain coverage therefore cannot blend receiver positions or let invisible layers replace a visible receiver. Only near-horizontal paving is accepted (geometric normal Y above 0.995); classification uses triangle-plane derivatives rather than authored smooth normals, which can cross the cutoff inside otherwise flat paving. Sloped terrain, walls, animated/programmed meshes and UI are excluded. The mask also captures native constant and slope-scale polygon depth bias, converts the offset into the stored receiver height, and keeps the original native render state intact. This prevents camera-dependent horizontal acceptance bands when comparing biased game depth to an unbiased replay. Final depth comparison uses the receiver plane's analytic depth interval over one pixel to admit native MSAA sub-samples. It does not expand its tolerance from neighboring foreground/background depths or impose a fixed world-space cap that rejects distant grazing paving; later foreground objects still have to lie inside that physical depth interval. The view ray reconstructs receiver depth from this height. The receiver height uses FP32. Admission also includes a world-height allowance for FP32 transform roundoff, scaled from the absolute camera-coordinate magnitude. Native terrain uses absolute-world vertex positions, where separately evaluated native and replay transforms can disagree slightly; a translated local mesh does not exercise that error. This allowance does not grow like a fixed device-depth bias at distant receivers. Rays retain the horizontal geometry normal, avoiding normals differentiated from quantized depth. A separate pre-atmosphere pass traces 24/40 screen-space steps with eight binary refinements, depth-supported eight-tap roughness filtering and silhouette/viewport rejection. Valid hits provide object reflections; missing or off-screen hits can use the captured native sky instead of invented geometry. The same shared 128-pixel sky cubemap used by WaterFX/fog is available when only surface reflections are active. A bounded unshadowed directional highlight follows the real game light and fades at night. Recognized texture grain reduces polish in dark grout; unknown materials and grass retain their native appearance. The optional targets cost 20 bytes per viewport pixel (about 41.5 MB at 1920×1080) and release when disabled or on Lost Device. This is deliberately opt-in and does not classify every material in every game map.

Receiver validation compares the analytic pixel interval in device depth and includes the actual native D16/D24 quantization interval. This avoids moving acceptance bands when the game uses D16: a fixed linear-depth percentage is insufficient at elevated camera positions. Reflection hits must also be above the receiving plane by more than depth and pixel-footprint uncertainty; roughness taps apply the same rejection, preventing paving depth steps from becoming displaced copies of the ground texture. Unsupported hits retain the existing environment fallback. When surface reflections and local lighting are both active, validated horizontal receivers supply their geometric position and normal to the light field, so quantized ground depth cannot turn their illumination into a staircase. Other receivers retain the existing depth-derived normals. This reuses the material mask without an additional render target or CPU readback.

Run `build/scene-fx-test.exe --surface-benchmark` for a GPU-synchronized 1080p workload with 28 paving draws and 1800 following terrain layers. It exercises camera directions and both quality tiers; it is a synthetic timing test, not a live-client FPS promise. Native proxy fixtures also overwrite queued vertex, index and texture data before the HUD boundary and verify unchanged output, with and without 8x MSAA. Surface fixtures test partial terrain coverage at 25/50/75/100 percent, monotonically increasing reflected energy, grass erasure and flat geometry with varying artist normals. The normal test build runs complete scene fixtures with D24 (with and without `--msaa`) and `--depth16`, plus D16/8x MSAA reflection and receiver-lighting fixtures via `--depth16 --msaa --surface-tests`. A native-resolution `--absolute-world --msaa` run additionally checks moving absolute-coordinate terrain at 1920×1080 with two projection ranges and terrain cell sizes. The separate full D16/8x MSAA suite still exposes slope SSAO banding; these reflection changes do not alter SSAO. Overhead camera sweeps test both quality tiers with native constant/slope-scale depth bias; an empty receiver must retain continuous sky fallback without reflecting its own paving. A contrasting checkerboard receiver additionally checks for false self-hits over fractional camera motion, and a moving-camera light fixture checks that illuminated paving retains its geometric normal. Moving-camera regressions blend 16/32 constant and spatially varying terrain layers at large map coordinates, vary camera yaw and fractional height during jumps, and reject even narrow missing-reflection bands. Both buffered and immediate draws are covered; an invisible layer at another height must leave the reflection unchanged.

Recognized refinement textures, pet-bead auras and elemental weapon materials use a separate aura pixel shader under Particle processing. `sfx_aura` controls colored midtone energy, a small material-local halo and smooth additive coverage enrichment; zero and opaque alpha endpoints remain unchanged. Unlike general particle styling, its strength is independent of the preceding particle draw count, so crowds do not progressively fade equipment glows. Native blend mode, geometry and animation remain intact. It adds no scene snapshot, particle replay or full-screen blur. Zero removes the additional aura treatment; the particle master switch restores the native pass. Detailed quality also reconstructs magnified aura texture sampling. These changes affect only the local modded client.

Detailed quality with positive Aura glow additionally uses a dedicated refinement shader for the seven exactly identified `sfx_EffectEnchant` color variants. An alpha-weighted nine-tap material filter broadens the native flame strokes into soft wisps, with slow periodic UV curls and smooth coverage at all four billboard edges. The existing aura slider blends toward this treatment; economical quality retains the previous aura shader. Pet beads and elemental weapons retain their existing treatment. The path uses the original texture, tint, native vertex fade, blending and depth test, without added geometry, render targets or retained motion history. Native emitter spacing and particle lifetime remain authoritative: this softens existing trail particles rather than inserting particles between them. Fixtures verify periodic continuity, monotone fading, zero/off behavior, crowd independence, depth isolation and shader restoration with zero/8x MSAA. `dist/FENB-preview.exe --refinement-preview` shows an animated native/detailed material comparison; `--refinement-capture` writes `build/refinement-preview.bmp`. Original local artwork is read-only and optional, with a synthetic fallback for clean checkouts. This is a material fixture; live running, camera movement, spacing and GPU cost still need in-game verification.

The DLL belongs beside `Neuz.exe`. Keep an existing `FENB.ini` when updating. A running game keeps its already loaded DLL and must be restarted to load a replacement.

Already-running clients keep their own **Effects**, **Unlock FPS** and **Run in background** switch states. Automatic reloads of the shared `FENB.ini` retain these three in-memory values, so another window's autosave cannot enable or disable them. Image tuning and profile files remain shared. Newly started clients read the saved switches as their initial values; explicitly choosing **Reload FENB.ini** applies the file's values only to the requesting client. No per-character configuration files or process IDs are persisted. Runtime tests exercise two instances reading/writing the same disposable configuration, independent switches, shared image changes and explicit reload.

### Panel updates and recovery

Opening the panel starts one background check per game session against the official repository's `releases/latest/download/FENB-update.json`. A newer stable release opens a centered modal in the selected language: English, Russian, Spanish or Brazilian Portuguese. The actions menu also exposes checking, download status and rollback. No network requests run on the rendering thread, and closed panels do not poll status. The DLL embeds the local PowerShell worker; it writes its working files into `FENB-update/` beside the DLL and runs the system Windows PowerShell hidden, without a separate updater executable. If PowerShell, networking or folder writes are unavailable, the panel reports failure and manual updates remain available.

The manifest has schema 1, a `digit.digit[a-h]` version, ZIP byte length and SHA-256. Downloads are restricted to HTTPS on GitHub and its release-asset hosts, with normal certificate validation, bounded redirects, timeouts and sizes. The archive checksum and exact entry allowlist are checked before extracting only the x86 PE DLL and `LICENSES.txt`. The shipped INI is never extracted into the game folder. Configurations, unknown INI values, language and personal profiles are retained in place. SHA-256 checks detect corruption; release authenticity relies on HTTPS and control of the official GitHub release account, rather than a separate signing key.

After verification the modal asks the player to close the game and relaunch through their usual launcher. The close button saves settings and sends a normal close request, never terminating or automatically relaunching the client. Replacement waits for the initiating process identity to exit; locked files cause a bounded failure. A localized desktop message confirms completion and invites the player to launch again. One verified rollback generation of the DLL and existing license notices is retained. A file-operation failure attempts automatic restoration; an interrupted transaction is detected by the next panel check and schedules restoration after exit. A regression in a successfully installed release requires **Restore previous version** from the panel. There is no blanket crash detector or forced game termination.

If the new version cannot open the panel, close all game instances and run the existing local worker from Windows PowerShell in the game directory:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\FENB-update\worker.ps1 -Mode Rollback -Root .
```

Keep `FENB-update/` until the new version has been verified; it contains the rollback snapshot and an `error.txt` with local failure details. Deleting it removes rollback history. The worker serializes operations with an exclusive lock, verifies backup hashes again before restoration and never installs into a different game directory.

For update-enabled releases, run `release.ps1` and publish both `FENB-<version>-win32.zip` and the generated `FENB-update.json` under the stable GitHub tag `v<version>`. Publish the manifest only with the matching verified ZIP. Old releases without the manifest remain installable manually; the panel cannot offer them as automatic updates. Packaging generates local artifacts only and does not publish anything.

### Local release packaging

Run `./release.ps1` from the repository root. It runs a normal `./build.ps1 -Tests`
build with an isolated `-OutputDirectory` under ignored `build/release-<id>/`,
then runs `node tools/verify-binary.mjs <built-dll>` before creating
`dist/FENB-<version>-win32.zip`, using the public version in `src/version.hpp`.
It does not publish a GitHub release or install files into a game directory.
For publication, run it from the source revision being released.

The ZIP contains exactly four files at its root: `d3d9.dll`, the shipped
`FENB.ini`, `INSTALL.txt` (English first, then Russian) and `LICENSES.txt`.
The packager verifies each archived payload against its source with SHA-256.
It never includes the rest of `dist/`, so preview/test executables, logs,
captures, old DLLs and custom profiles cannot enter through a directory glob.
All nine built-in profiles are embedded; no presets folder is shipped. After
tests finish, the packager recopies `config/FENB.ini` to avoid shipping settings
temporarily saved by the native fixtures. Shared `dist/` output is not an input.

`node tools/prepare-distribution.mjs` regenerates `dist/LICENSES.txt` from the
original FENB, Dear ImGui, Inter and SMAA license files and copies
`docs/INSTALL.txt` to `dist/INSTALL.txt`. The normal and diagnostic PowerShell
builds also run this helper for their respective output directories. Original
license files remain tracked in their existing locations. Older local output
is preserved but excluded from the ZIP.

No compatibility guarantee is made for other Flyff clients.

WaterFX has a separate reflections page with Sky Only, SSR Performance (24 automatic steps) and SSR Quality (48 automatic steps). Explicit controls cover 50/75/100% target size, 8–64 ray samples, 4–16 binary refinements, range, start bias, depth tolerance, confidence cutoff and soft sky fallback. Legacy configurations retain their previous quality tier until a method is selected; zero explicit ray steps means automatic. Planar and Hybrid are unavailable: no verified world-scene replay path is exposed. Screen-space omissions and occlusions remain fundamental limitations.

Diagnostic water records include all 23 PS constants, native depth-surface format and reflection encoding. Run `node tools/inspect-water-reflections.mjs <capture directory> <ignored output directory>` to export confidence and decoded radiance bitmaps plus a histogram/depth-format report. Existing straight-color capture bundles remain readable. Confidence does not by itself identify a rejection reason; the tool does not infer one. These readbacks remain opt-in diagnostic work.

SkyFX distinguishes the native `sundisk.bmp` / `lenzflare_008.tga` sun-disc identities from the other lens elements. The disc receives an analytic bright core and smooth additive aureole, controlled by Sun halo, while rainbow lens ghosts stay faint. The sky shader also evaluates an antialiased angular core and broad soft glow in the directional sun position; night-light gating remains in place. These are native sky/material passes, not a full-screen translucent disc, and ordinary opaque scene rendering covers them. Zero Sun halo restores the native identified disc; disabling SkyFX restores all native flare passes. Sun-ray depth occlusion remains a separate effect.
