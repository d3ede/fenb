# FENB 0.2d

FENB is a graphics mod for Flyff, inspired by ENBSeries. It uses a Windows x86 Direct3D 9 proxy, C++20, precompiled shaders and a native Dear ImGui settings panel.

## Controls and profiles

- **Shift + Enter** opens and closes the panel without opening game chat. Each opening centers the panel and returns to the main image page. The open panel can still be moved.
- **Effects** enables or disables all FENB rendering. Color correction, Bloom and WaterFX also have individual switches.
- **Right Shift + F12** toggles the master effects switch immediately, with or without the panel. Repeated keydown messages do not toggle it repeatedly; the chord is not forwarded to the game. Left Shift + F12 and ordinary F12 retain their native behavior.
- **World**, between the image page and **Language**, opens local time and weather controls. Each section has an independent enable switch: off follows the game. Drag the time slider in one-minute steps, type `HH:MM`, or use the arrows. **Freeze time** holds the selected hour; otherwise it advances at the native clock's pace. Weather offers **Clear**, **Rain** and **Snow**, with a live precipitation-intensity slider. Both overrides default to off and respect the master effects switch.
- **Language**, after **World**, switches between **English** (first and default) and **Русский** immediately. In narrow panels the selector reads **EN** or **RU**. The choice is saved as `language=en` or `language=ru` in `[General]` of `FENB.ini`; profiles and effect resets preserve it. Older configurations without this key use English. Custom profile names and filenames stay unchanged.
- Drag a slider, double-click its track to reset it, or click the number to type. The small arrow buttons use a parameter-specific step. The reset icon is shown for changed values.
- Edits save automatically to `FENB.ini`. **Ctrl + S** saves immediately.
- **Create…** beside the profile selector, or **Create profile…** inside its dropdown, saves the current settings under a name. Type the name and press **Save**; the profile appears in the selector. For a loaded custom profile the toolbar offers **Save…**. Existing names require the explicit **Replace profile** button. Files live in `FENB-presets`; compatible `.ini` files can also be copied into that folder.
- The main-page order is **Light and atmosphere →**, **Antialiasing →**, **WaterFX →**, **Color correction**, **Bloom**. WaterFX opens its own page. Its navigation arrow shares the reset-icon column. **Back** returns to the image controls.
- **Light and atmosphere →** opens compact collapsible controls for SSAO, Sun Rays, SkyFX, fog, DoF, adaptation, lighting balance, vegetation and local illumination. Each effect has its own switch and parameter reset. **Antialiasing →** contains FXAA, SMAA and native MSAA.
- The reset icon in each section heading resets only that section's parameters. Effect enable switches, other sections, the global switch and the FPS option are preserved.

**Default / Основной** is the built-in starting profile. Its entire WaterFX block preserves the owner's active water configuration: 0.05 wave shading, 9.5 wavelength, 0.4 speed, 0.8 ripples, 0.74 opacity and sky, detailed SSR, and caustics disabled. Other effects form one combined visual setup: moderate SSAO and Bloom, a stronger daylight ray source, recognized day/night sky and clouds, distant height fog, subtle far DoF without near blur, capped adaptation, warm local surface lighting, SMAA and night foliage fill.

The built-in list contains exactly five looks: **Default / Основной**, **Clear water / Чистая вода**, **Golden light / Золотой свет**, **Soft atmosphere / Мягкая атмосфера**, and **Night lights / Ночные огни**. They replace the earlier Neutral/Warm/Cool/Soft light set. Clear water uses calmer, more transparent water and lighter processing; Golden light uses warm color, broader bloom and restrained caustics; Soft atmosphere uses gentle highlights, ripples, haze and far focus; Night lights lifts dark detail and emphasizes local glow without forcing the game clock. These are image looks, not time-of-day overrides.

All five are compiled into the DLL; the default image settings come from `config/FENB.ini`, with named variations in `config/builtins.json`. `node tools/embed-presets.mjs` regenerates `src/generated/presets.hpp`, and both build paths keep it in sync. No shipped `.ini` is added under **My profiles**. The old saved copy of Основной can be archived when migrating to the identical built-in, without discarding user edits. Custom files remain independently supported. Image-profile changes preserve the master switch, language, hardware/FPS choices and local time/weather controls. Modified built-ins retain their translated name with an asterisk, and can be saved as a custom profile.

The lower-left corner shows the public version, **0.2d**, followed by save status. Public versions use the form `digit.digitletter`.

## When an effect is visible

Time and weather use an opt-in adapter for the SHA-256-verified Homesickness Neuz revision. Unknown clients and the synthetic preview can configure the values but do not apply native overrides. The adapter checks PE identity, relocated pointers, code signatures and memory protections before installing a reversible render-vtable hook. It temporarily substitutes the visible clock fields and precipitation data only during rendering, restoring the game's clock, weather selection, particle history, option and texture ownership afterwards. Network state, server clocks, dates and simulation remain native. Rain/snow use the client's artwork and bounded native particle capacity, with a separate local animation history. Maps with custom or fixed environments may limit the result. Settings are stored in `[Environment]`; old configurations retain native time and weather.

Sun Rays need daytime directional illumination near the camera's view and sky gaps interrupted by geometry; pointing down at night is not a useful comparison. They do not create light shafts in every scene. SkyFX now recognizes the actual night skybox03/cloud03 passes from the supplied capture, which the earlier day-only catalog missed. When an enabled effect lacks a supported sky, light source or scene depth, its expanded controls show that condition rather than silently suggesting a working effect.

Foliage gaps in water reflections are a limitation of the current screen-space reflection path: the main camera's depth/color does not contain hidden crown undersides or off-screen branches. Fine leaf silhouettes can also fail depth-hit validation. A detailed underside in the original model is insufficient without a separate reflected-camera geometry pass. This update does not claim complete planar reflections or fill those gaps with invented tree geometry.

Water reflection tracing now has a separate material pass over the same native water geometry. It rejects depth discontinuities in all four neighboring directions, reflected backface hits and initially occluded rays. Unsupported hits use the sky environment. Object reflection coordinates follow the geometric surface; animated ripple shading, refraction and glints remain enabled. Object Fresnel is filtered toward the macro surface so small ripple normals do not cut bridges into strong light/dark stripes. The extra RGBA8 target costs four bytes per viewport pixel and is released when tracing is inactive. Each shader stays within the Shader Model 3 instruction limit.

**Lighting balance** provides bounded ambient fill before shading common lit opaque fixed-function materials, including supported props and weapon paths, without an object-name whitelist. Daytime material lighting is preserved. A second, hue-preserving contrast curve covers the entire world image, including programmable/skinned and unlit paths. Its pivot follows GPU mean log luminance through independent FP32 history, lifting dark detail and restraining unusually bright models. Gain is bounded, zero intensity is neutral, and black pixels remain black. Reduction targets are shared with brightness adaptation; only two tiny scalar histories are added, with no extra full-size image target or CPU readback. It cannot recover detail already absent from the source color. The two mechanisms are controlled by the same independent section; ordinary exposure remains separate.

Shallow water retains its optical surface: shore softness acts on a narrow edge and retains a small surface response instead of suppressing it across a broad shallow band. A restrained minimum optical layer covers valid horizontal water pixels even when the sampled floor is nearly coplanar; water deeper than 0.35 world units retains the original absorption path. The original water mesh, depth testing and texture cutouts define coverage, so the minimum layer does not paint the dry background outside that mesh. Absorption coefficients are prepared on the CPU once per material replacement rather than evaluated logarithmically per pixel.

## Scene rendering, lighting and antialiasing

Scene processing runs at the existing pre-HUD boundary. Camera matrices and the viewport come from the first compatible main-scene opaque draw. Orthographic shadow passes, other render targets, unsupported projections and later 3D portraits cannot supply this camera. Spatial effects use a separate GPU depth snapshot through the same optional NVIDIA path as WaterFX; FXAA, SkyFX, exposure and vegetation fill do not require that backend. Unsupported depth leaves the affected effects inactive rather than inventing geometry.

- **SSAO** reconstructs view-space receiving positions and normals, samples a bounded world-space radius with 8 or 16 directions, fades with distance and uses depth-weighted upsampling. Receiver normals use the spatial-field footprint and snapped depth sample positions, avoiding false horizontal occlusion bands on unoccluded slopes. It is contact occlusion on visible geometry, not new world shadow maps.
- **Sun Rays** projects the enabled directional light and integrates a sky/depth occlusion mask at reduced resolution. Foreground geometry can interrupt the light. These are screen-space crepuscular rays, not a world-volume simulation; off-screen occluders cannot be recovered.
- **SkyFX** changes only exactly identified sky/cloud passes. It preserves native texture-stage RGB/alpha operations and supported 2D texture-coordinate transforms, including cloud scrolling. The native sky art supplies day/night brightness; a luminance-preserving atmospheric tint modifies blue regions while retaining cloud and star detail. Cloud contrast keeps the original alpha. The directional daytime halo remains independently adjustable. This avoids multiplying SELECTARG1 texture color by unrelated vertex RGB or darkening the sky with object diffuse lighting. Sky detail reconstructs magnified sky/cloud texels with a bounded nine-tap Catmull-Rom filter; it does not create new high-resolution cloud artwork. Night processing suppresses coarse star blobs and adds procedural fine stars anchored to sky directions. A screen-footprint Gaussian keeps these points round and antialiased as the camera rotates. Native daylight fades the new stars, and cloud-only passes cannot receive them. Sky detail at zero retains native texture sampling; Fine stars controls their brightness. The same material replacement participates in water cubemap capture, needs no additional texture or render target, and retains native day/night/weather transitions.
- **Fog** adds distance and height-dependent atmospheric extinction to visible opaque geometry. Height density uses the midpoint of the camera-to-surface segment. A color snapshot before the first opaque draw is reduced to diffuse mean sky radiance; distant surfaces converge to that atmospheric color, including across the native linear fog interval. Moon and cloud texture details are never projected onto foreground surfaces. Color controls tint the intermediate haze without creating a separate far-color wall. This does not extend native draw distance, recover culled terrain or undo native fog already present in the input. The optional full-size sky snapshot costs four bytes per viewport pixel, plus approximately 2 KiB for its 16/4/1-pixel FP16 reduction chain.
- **Depth of Field** uses manual focus distance, a sharp range, a bounded 12-tap blur and depth rejection at foreground boundaries. Near blur has its own strength. Bright image features retain their sharp cores through a conservative brightness heuristic; this is not a separate particle-depth layer. It is intended as an optional cinematic control, not physical aperture simulation or character tracking.
- **Brightness adaptation** reduces mean log luminance through 64/16/4/1-pixel GPU targets and smooths a persistent FP32 EV value with separate bright/dark rates and limits. FP32 history avoids quantization stalls at high render rates. The pre-HUD scene supplies luminance. There is no production CPU image readback. Disabling adaptation or resetting the device releases/resets its history.
- **Night vegetation** identifies the common tree texture families by exact first-mip identity and adds bounded ambient fill only during their compatible fixed-function draws. Original material and ambient state are restored immediately. Directional illumination, alpha cutouts and textures remain native. A daytime fixture verifies unchanged output. Unknown foliage families are left alone.

**Local surface illumination** supports up to eight native point lights and 32 recognized emissive draws. Each emissive draw is replayed into its own 32x32 UV-space tile, then reduced to a source position and radiance. The atlas stores positions relative to a stable world origin rather than screen bins, so camera rotation and projected size do not move or duplicate a lamp. Recently observed sources persist for up to 0.5 seconds with a short fade when native culling stops submitting them. Native vertex color, texture factors and alpha fading are retained for supported simple texture stages. Unknown, programmable and complex passes remain unchanged.

Emitter slots match material and nearby world anchors rather than transient vertex buffers or exact floating-point bits. Halo layers around one bulb share a slot. The cache retains up to 32 spatial sources, prioritizes nearer candidates with distance hysteresis, and permits at most 96 capture draws per frame so early distant halos cannot consume the entire discovery budget. This bounded cache cannot illuminate a source the client has never submitted; briefly missing sources retain the existing half-second fade.

Receiver normals use neighboring samples on the same depth surface; the light field is upsampled from its actual texel centers with depth rejection. A neutral regularization term fades weak depth matches instead of amplifying a nearly unrelated field sample into an isolated bright pixel. Bounded reflectance recovery and a soft per-channel lighting response let a dark receiver brighten without hard additive clipping. A small finite-source angular approximation softens the near-light terminator; it does not reconstruct smooth mesh normals or real area-light shadows. The old sparse screen-space shadow march has been removed: its discrete blockers stamped shifted character silhouettes into the scene. These additional lights are **unshadowed** until a reliable light-space geometry pass is available, so walls can still leak light. This is not full albedo reconstruction, shadow mapping or global illumination. Emitters not previously submitted by the native renderer and hidden receiving surfaces remain unavailable. Capture and reduction stay on the GPU without production image readback or retained game geometry.

Known native `lenzflare_001` through `008` material passes use a smooth analytic warm halo under SkyFX. Exact texture fingerprints and the captured depth/blend state restrict the replacement to the native flare path; ordinary particles, lamp glow and HUD materials retain their original rendering. Native quad placement and vertex fading remain in control. **Sun halo** controls its strength along with the directional sky halo.

The antialiasing page has two compact selectors: **Off / FXAA / SMAA**, followed by **MSAA: off / x2 / x4 / x8**. The MSAA selector displays and selects the mode actually active in the client, including when `msaa_samples=0` preserves the game's choice. FXAA and SMAA run after scene lighting, fog, grading and Bloom, before the HUD. They reuse the existing full-size ping-pong targets instead of adding another full-size AA output. SMAA uses the original three-pass SMAA 1x High preset, with color edge detection, diagonal searches, area/search lookup textures and neighborhood blending; it needs no motion vectors or depth. Existing `fxaa_strength` and `fxaa_threshold` values remain supported in configuration files. `smaa=1` selects SMAA in preference to FXAA when both keys are enabled. Spatial antialiasing can be combined with MSAA.

MSAA changes request the host's Lost Device recovery after a completed main-chain Present. The proxy reports DEVICELOST, then DEVICENOTRESET when the real device is ready; the client releases its own resources and calls Reset. FENB never resets the device behind the client's back. Reset uses the current in-memory choice, so it does not wait for autosave. The section reset restores the game's original sample type/quality; `msaa_samples=0` remains supported for existing configurations. Color/depth sample support, the existing DISCARD swap effect and the pinned client guard are checked; the bundled preview also supports this path. Unsupported or failed overrides retain the game's fallback parameters, and real device-loss errors propagate unchanged. Native preview fixtures verify live mode changes; live Flyff recovery still needs validation. MSAA covers geometry and does not by itself remove every alpha-test or shader alias. TAA is not implemented.

The economical quality tier uses quarter-dimension spatial fields; detailed uses half dimensions and more AO samples. FXAA reuses the existing color target when combined with spatial effects. Memory depends on the enabled paths and quality tier. The optional reflection and sky-backdrop targets together add about 14.8 MiB at 1920x1009 when both SSR and fog are active, excluding game MSAA targets, driver allocations, fonts and UI. GPU/FPS cost in the live client is not yet measured. Native fixtures cover individual rendered effects, camera-orbit source stability, fading, absence of displaced light silhouettes, day/night vegetation, state restoration, HUD isolation and Reset with zero and 8x MSAA; they are not live visual acceptance.

## World particles and water footsteps

The **Skill effects** section in Light and atmosphere controls intensity, saturation, material-local glow and texture-edge softness. Supported native particles retain their geometry, timing, UV animation, vertex fading and depth visibility. Simple fixed-function RGB/alpha stages are reproduced before styling; complex stages, programmable materials, HUD quads, portraits and unknown textures are left unchanged. Styled additive light particles use a hue-preserving energy shoulder and bounded screen composition instead of saturating the LDR backbuffer with overlapping additions. Native alpha coverage is retained; softening acts only on dim texture edges. Intensity, chroma and halo enhancement fade toward their native values after 64 supported draws in a frame, while bounded composition remains active. Neutral style settings retain exact native blending. Soft edges are texture filtering, not depth-based soft particles; this does not create new spell geometry or animation.

Recognition uses exact first-mip upload hashes, cached on managed textures and invalidated with texture updates. `tools/sfx-materials.json` contains source identities and decoded ARGB8 fingerprints; `node tools/sfx-catalog.mjs <client directory>` verifies those assets and regenerates `src/generated/sfx_catalog.hpp`. The runtime contains identities only, not copied game textures, and performs no file loading or GPU image readback for styling. Particle replacement saves only its shader constants and changed material states; it does not create a full-device state block or rebind render/depth targets per particle. Cached FVF checks reject ordinary world and HUD draws before the material path.

**WaterFX → Surface → Water footsteps** is independent of Skill effects. Its existing `sfx_wake` configuration key remains compatible; resetting Skill effects no longer changes it, while resetting the water surface restores its default. The captured water-running material is also used by an archer skill. A separate horizontal-quad, texture-stage, blend-state and visible-water signature restricts its wake replacement. A clean world-color snapshot supplies local refraction instead of the native additive white ring, without adding a white highlight or tint. The original expanding quad animation remains authoritative. Late particles cannot capture a source containing the HUD: the snapshot is refreshed at the pre-HUD boundary, or the replacement retains the native draw. A zero footstep strength restores native rings. This snapshot adds four bytes per viewport pixel when used (approximately 7.4 MiB at 1920x1009), releases on Reset/disable and does not require readable scene depth. No physical water simulation or interaction-driven mesh is added.

Bloom retains headroom around bright colored cores instead of adding another white layer directly onto them. These changes reuse existing passes and targets; no additional full-resolution particle layer is allocated.

Native fixtures check neutral fixed-function parity, overlapping particle clipping, shader/blend restoration, alpha fade, HUD/camera guards, depth occlusion, real water DDS recognition, refractive wake rendering, weak-depth light rejection, bright DoF core preservation, colored Bloom headroom and resource release with zero and 8x MSAA. Live gameplay appearance and FPS remain to be validated.

## Native client frame pacing

The original flag-only unlock accelerated gameplay because the client calls its simulation once per main-loop iteration. The replacement installs a gate on the verified application's `FrameMove` virtual method before clearing the native frame limiter. Rendering remains independent; simulation uses the original 16 ms cadence (62.5 updates/s) and receives a fixed 0.016 s delta. Real wall clocks and network timers are not scaled. Short stalls allow bounded catch-up; long stalls start a fresh cadence without replaying a loading screen. Render-time animation interpolation is not added.

Enable **Снять лимит FPS** in the panel's actions menu, or set `unlock_fps=1` under `[General]`. It is off by default, independent of the effects switch, and preserved when changing image presets. Unknown clients are left unchanged. This implementation is pinned to the inspected Homesickness `Neuz.exe` SHA-256 `ce32e350c6002496acf9e8774275784971186e6144901f7c2c7d9b37a4aa41a1`; it verifies relocated frame gates, the application and its update method, and code/data protections. The in-memory vtable entry and limiter flag are restored when disabled or the last device is released. No EXE file or executable instructions are patched. Driver and VSync limits still apply.

Native tests invoke the actual x86 callback through a disposable vtable and compare simulation counts and elapsed time at 30, 60, 144, 500 and 1000 render FPS. These tests do not establish live gameplay compatibility: movement, attacks, jumping, world and UI animation still require comparison in the supported client. A high render count does not imply interpolated simulation or a guaranteed 500 FPS.

If an older loaded DLL has the flag-only unlock enabled, turn it off before continuing. Replacing the DLL takes effect only after restarting the client. Regression tests use disposable mapped images and callbacks; they do not modify a running game or installation.

## WaterFX implementation and limits

WaterFX replaces the material only for the two water texture families identified in the Homesickness Neuz render capture. Identification uses exact first-mip SHA-256 fingerprints, cached as texture-private metadata. The draw must also match the observed fixed-function layout and transparency state, belong to the main backbuffer and occur before the HUD. Unknown textures and unsupported states retain the original renderer. No game memory or vertex-buffer readback is used.

The material supplies animated wave normals, two drifting and rotated normal-map layers, adjustable opacity, a turquoise tint, GGX directional-light glints and Fresnel reflection. **Neuz mesh positions are preserved:** the wave-height control changes shading normals without lifting independently drawn tiles or river skirts. No geometric displacement or tessellation is added. Camera-relative interpolated positions keep geometric derivatives stable at large world coordinates. A deterministic 32-wave spectrum generates a single 128-pixel normal texture with a complete mip chain once. The original water texture RGB remains a separate, low default contribution; texture alpha preserves cutouts. Ambient light, material properties and the enabled directional light illuminate the water body. The analytic sky fallback follows that illumination at night.

Opacity is controlled by FENB and texture cutout coverage. Legacy vertex and material alpha are not multiplied into it: a zero vertex alpha channel previously made the material almost invisible and defeated the opacity control. The native water regression fixture now uses zero vertex alpha and verifies that both opacity settings still produce distinct visible results.

Refraction uses a GPU-only color snapshot taken once before the first matched water draw in each frame. It does not sample the live render target or recursively refract previously drawn FENB water. With valid depth, the material computes the optical path between the water surface and opaque scene, applies channel-dependent absorption, softens the shoreline and fades fine normals at contact. Refracted samples above the water plane or in front of its surface are rejected. Without valid depth, it retains uniform transparency and conservative distortion; foreground color leakage is still possible in that fallback. Only geometry already drawn before the snapshot is available.

Sky reflection captures the exact identified `skybox01`–`skybox06`, `cloud01`–`cloud05` and `rartesia_cloud` families, including low-resolution versions. It replays their fixed-function geometry into a 128-pixel cubemap, updated at most four times per second. Only their original DrawPrimitive calls are repeated, with six camera orientations, the original texture stages and no depth buffer; no world scene is replayed or retained. The water samples this actual sky/cloud rendering with its reflected normal. Unknown sky textures or unsupported paths use the analytic gradient. A frame without a matched sky cannot reuse a stale map from another scene. The native fixture verifies the capture, cubemap selection, main-target preservation and state restoration; appearance in the live client still needs checking after restart.

Depth-based optics currently use the optional NVIDIA driver path: registered D16/D24 scene depth is copied into an INTZ texture through [NvAPI_D3D9_StretchRectEx](https://docs.nvidia.com/nvapi/group__dx.html). The native fixture verifies actual sampling of the resolved depth and rendering with both D16 and D24 at zero and 8x MSAA. The copied source remains the actual depth surface used for scene rendering. Driver functions are loaded only from the system directory; no NVAPI redistributable is required. Unsupported drivers, formats, projections or failed copies use the fallback material. RESZ support alone is not assumed.

Water and scene effects keep separate snapshots because their capture boundaries differ. They share reference-counted NVIDIA API and resource-registration ownership: disabling or destroying one consumer must not unregister the other's live game depth surface. A native regression repeatedly toggles and destroys both consumers, then resets the device, for D16/D24 with zero and 8x MSAA.

SSR traces the copied opaque depth with 12 or 24 steps and twelve bounded refinement iterations. Its ray uses the actual geometric plane, independently of animated wave normals. Accepted world-color samples receive no additional screen-pixel warp; waves change lighting and Fresnel strength without relocating reflected objects. A source-format-aware hit tolerance and a separate distance-relative silhouette threshold discard loose hits without treating a sloped bank's depth gradient as D24 quantization error. Steep skirts suppress reflection, refraction distortion and specular glints. Refraction rejection tests the local plane in view space, including sloped river sections. Missing hits fade to the sky environment.

SSR still sees only visible, previously rendered geometry: off-screen objects, hidden surfaces and later transparent passes cannot be reconstructed. There are **no complete planar world reflections or reflection scene replay**. D16 precision, screen-space disocclusion and defects already present in the source geometry can still produce artifacts; stability tests are not proof that every map is seam-free. Sun glints use the enabled directional light. Full dynamic shadow maps remain separate work.

The optional **24-bit water depth** action (`precise_water_depth=1`, enabled by default) upgrades only an automatically allocated D16 buffer in the pinned Homesickness client, at CreateDevice/Reset. Format, depth-stencil and the existing MSAA quality are checked before use. Allocation failure retries the original D16 parameters; Lost Device is propagated. Color format, dimensions and MSAA are unchanged. The option requires a client restart. It adds roughly 32 MiB of driver depth storage at 1920x1080 with 8x MSAA; actual driver allocation may differ. Distant shallow-water stripes may come from D16 precision, but fixing every reported beach artifact is not yet live-verified.

Optional caustics reconstruct receiving positions and normals from copied opaque depth and evaluate refracted directional-light focusing in a separate reduced-resolution pass. A finite-difference ray-map Jacobian gives bright and dark concentration patterns, with a small wavelength-dependent IOR variation controlled by **Dispersion**. The field is sampled only by underwater transmission; SSR reads the unchanged scene snapshot. Focusing uses an approximate two-world-unit slab rather than a full ray trace through arbitrary water geometry. Real optical path length fades the result; directional light controls day/night strength. Flat normals produce no patterned focusing. This is not volumetric scattering, light-occlusion tracing or a generic RGB screen filter. The main profile retains the active water configuration with caustics disabled; the parameter remains independently adjustable.

Color and depth optics need one full-size 32-bit color target and one INTZ depth texture, copied at most once per water-containing frame. Together with the 384 KiB sky cubemap and 85 KiB normal mip chain, this is about 15.2 MiB of owned GPU resources at 1920×1009 before the optional caustic field. Enabled SSR adds another RGBA8 target of about 7.4 MiB and a replay of each replaced water draw for reflection validation; disabling SSR releases that target. The field adds about 0.46 MiB at quarter dimensions or 1.85 MiB at half dimensions and one pass per water-containing frame. There is no CPU image readback or persistent copy of game geometry in production. Zero refraction, absorption, SSR and caustics together release the color target; zero absorption, SSR and caustics release the depth texture; zero sky contribution releases the cubemap. Normals retain their small managed texture until Reset or teardown. The pixel shader fits the 512-slot Shader Model 3 budget. Resources are released for Lost Device/Reset and recreated lazily. Native fixtures check object reflections, shallow/deep transmission, caustic receiver isolation, day/night strength, flat-water neutrality, both field resolutions, resource release and restoration; they do not establish live FPS cost or visual parity with another game.

The stability fixture also compares zero and maximum wave amplitude: reflected-object support must overlap by at least 90%, and a constant-color rendering of two water levels joined by a vertical skirt must remain pixel-identical. It runs at the origin and near world coordinates (7000, 100, 3300), with both non-MSAA and 8x MSAA paths.

Restoration also preserves the input-binding changes required by [DrawPrimitiveUP](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-drawprimitiveup) and [DrawIndexedPrimitiveUP](https://learn.microsoft.com/en-us/windows/win32/api/d3d9/nf-d3d9-idirect3ddevice9-drawindexedprimitiveup). Native regression tests exercise both paths.

Post-processing runs before the first screen-space HUD draw, preserving interface colors and later 3D portraits. Present and swap-chain Present remain supported.

## Build and checks

The local portable LLVM-MinGW toolchain lives under `.tools/llvm-mingw-*-ucrt-x86_64`. Run `./build.ps1 -Tests`, `./dist/FENB-preview.exe` and `node tools/verify-binary.mjs`. The test build checks settings, exact HUD colors, native water material selection and restoration, transparency, Reset, input handling and panel interactions. The water fixture test reads the locally installed DDS; it reports a skip when that optional game asset is absent. Test screenshots and configuration files stay in ignored build folders.

Use `-Diagnostics` only for the opt-in bounded pipeline capture. The normal build has no capture code. The diagnostic menu delays a three-frame capture by three seconds so the panel can be closed and a wake or splash reproduced. Native rings and splash particles are still rendered by the game; their draw states must be captured before integration. A CMake x86 build is also described in `CMakeLists.txt`; the PowerShell/LLVM build is the verified local path.

`node tools/water-catalog.mjs <World/Texture directory>` regenerates the checked-in exact water fingerprints. Proxy interfaces are generated with `node tools/generate-proxies.mjs <d3d9.h>`; do not hand-edit generated forwarding methods.

`node tools/emitter-catalog.mjs <client directory>` regenerates emissive and common-tree material identities. `tools/emitter-decoded.json` also records verified ARGB8 upload identities, guarded by the compressed source hash. The optional offline `tools/texture-fingerprint.cpp` helper uses system D3DX9 to derive such identities; D3DX is not a production DLL dependency and no game textures ship in this repository.

The DLL belongs beside `Neuz.exe`. Keep an existing `FENB.ini` when updating. A running game keeps its already loaded DLL and must be restarted to load a replacement.

Dear ImGui and Inter license notices ship with the build. No compatibility guarantee is made for other Flyff clients.
