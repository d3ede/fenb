# FENB 0.7a

Independent background activity and native timing fixes for FENB, a graphics mod for Flyff inspired by ENBSeries. This release includes all changes since 0.6a.

## Background activity

- Added **Run in background**, an independent switch in the panel footer beside **Unlock FPS**, translated in English, Russian, Spanish and Brazilian Portuguese. It is off by default and can be used with or without FPS unlock on supported Homesickness clients.
- When enabled, native world updates and existing attacks continue while the client is inactive or minimized. The normal render/post-render/Present lifecycle, player-control updates and camera follow remain active; desktop key presses do not become held game input.
- Both the framework loop and the separate client entry-point loop are connected, avoiding the native inactive-window draw throttle. Otherwise-blocking message waits use bounded, message-aware deadlines; queued messages, shutdown and native device-loss recovery remain supported.
- With FPS unlock off, foreground simulation and the native FPS cap stay unchanged. Disabling background activity restores native inactive-window resource saving. Profiles and effect resets preserve the setting.

This feature continues native client work; it does not create attacks, change server attack speed or guarantee that every skill keeps running. Long minimized combat sessions still need live verification. Background rendering can use more CPU/GPU resources than the game's normal inactive mode.

## Native timing fixes

- Ordinary auto-attacks retain the native world-update and target-request completion order, preventing an intervening idle clip when a continuous update finishes an attack. Target changes, pending movement/skills/items and invalid player/world state reject continuation. Hit-stop duration and transition blending retain native timing.
- Particle models share a legacy update budget across world, attachment and render-time callers. Additional render passes cannot advance motion, animation or expiry again; native completion, looping and destruction ownership are preserved.
- Sky texture drift and the separate terrain cloud layers, including cloud-like surfaces below islands, advance by elapsed time instead of render count. Existing phases and native drift rates are retained.

## Multiple clients

- While clients are running, reloading a shared configuration preserves each client's **Effects**, **Unlock FPS** and **Run in background** switches. Toggling one client's switches no longer changes those live switches in another client.
- Startup still reads saved settings. Other shared visual configuration changes continue to reload normally.

## Install or update

**From 0.5a or later:** use **FENB updates** in the panel's **…** menu. Download the update, close the game when prompted, wait for completion and launch normally. Existing settings, language and custom profiles are preserved, with the previous DLL available for rollback. Enable **Run in background** explicitly if you want the new behavior.

**Manual installation:** download **FENB-0.7a-win32.zip**, close the game and copy `d3d9.dll` beside `Neuz.exe`. Replace `LICENSES.txt` with the supplied copy. New installations also need the included `FENB.ini`; updates should keep the existing configuration and `FENB-presets/`. Users on 0.4a or earlier need this manual replacement once. `INSTALL.txt` contains English and Russian instructions. Open the panel with **Shift + Enter**.

The release includes the matching **FENB-update.json** for automatic updates and a **.sha256** checksum for manual verification. The updater requires Windows PowerShell, Internet access and write access to the game folder.

Requires Windows and a compatible **32-bit DirectX 9 Flyff client**. Native adapters target supported **Homesickness Flyff** layouts and reject incompatible code; arbitrary client or compiler changes remain unverified. Depth-based effects still require a supported NVIDIA driver depth-copy path. The published DLL has diagnostics disabled. See the [README](../../README.md) and [rendering notes](../RENDERING.md) for compatibility, screenshots and recovery details.
